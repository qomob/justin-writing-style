## 二、触发验证（Trigger / Anti-Trigger Prompts）

部署后由人工或自动化用下列 prompt 真实跑一遍，核对 routing 与 expected 命中。

### 应触发（Trigger）
1. "用冷叙述的写法，写一篇分手当晚的场景。"
2. "帮我用克制文体写一段创业失败的自述开场。"
3. "写一篇'justin style'那种表面平静实则崩塌的叙事。"

### 不应触发（Anti-Trigger，应路由到其他 skill 或拒绝）
1. "帮我写一封煽情的演讲稿。" → 命中 description 的"不适用于：演讲稿"
2. "写一篇产品营销文案，要热血一点。" → 命中"不适用于：营销文案"
3. "帮我润色这篇英文学术论文的摘要。" → 命中"不适用于：学术论文"

## 三、期望核对点（节选自 Golden Set）

- 全文直接情感形容词 = 0
- 全文感叹号 = 0
- 冷开场：两个并置事实，无背景交代
- 对话无引号、无修饰动词
- 数字密度：每 80 字内至少 1 个具体数量/专有物件
- 结尾是清零句，无升华
- 全部人物/机构为虚构或化名，无真实人名与可识别真实对象

## 四、重新验证周期

每 90 天（T+90d）用上述 Trigger / Anti-Trigger 复跑一次；命中率下降即触发 Improve 模式（参考 `honest-boundaries.md` 的演进方向）。
